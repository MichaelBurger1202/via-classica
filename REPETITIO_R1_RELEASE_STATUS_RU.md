- SHA-256 всех файлов baseline сопоставлен с байтами исходного ZIP: совпадение.
- Контрольные суммы кандидата: `SHA256SUMS-15.2-r1.txt` (проверять его, а не исторический `SHA256SUMS-15.2-draft.txt`).
- Опубликованный origin и пользовательский `localStorage` не затронуты.

## 2. Точный список изменённых файлов (5)

1. `styles.css`: минимальная область касания 44×44 для кнопок удаления регулярных занятий, высота селектора режима дня >=44, высота ссылок на официальные страницы в карточках олимпиад >=44. Алгоритмы и данные не изменены.
2. `sw.js`: офлайн-запрос отсутствующего JS/CSS/JSON больше не получает ошибочный HTTP 200 с HTML главной страницы; только навигации получают `index.html` как fallback, прочие отсутствующие файлы получают HTTP 503. Обновлён cache name и версии ресурсов.
3. `index.html`: изменены только версии URL `styles.css`, `app.js`, `manifest.webmanifest` на `15.2-r1` для корректного обновления кеша.
4. `app.js`: изменена только версия URL регистрации Service Worker на `15.2-r1`. Остальная логика неизменна.
5. `manifest.webmanifest`: обновлено внутреннее поле `version` на `15.2-r1-candidate`; название, scope, start_url и иконки сохранены.

Добавлены **два документа**, не меняющие функциональность: `REPETITIO_R1_RELEASE_STATUS_RU.md`, `SHA256SUMS-15.2-r1.txt`.

Остальные файлы сайта, включая `planner.js`, `english.js`, `diagnostics.js`, `calendar.js`, `storage-guard.js`, JSON-источники и иконки, **побайтово совпадают** с v15.2-draft.

## 5. Политика доказательств и ограничения

- При прямом открытии `http://127.0.0.1:8765/index.html` Chromium возвращает `net::ERR_BLOCKED_BY_ADMINISTRATOR`. Поэтому нативные `localStorage`, реальная SW-регистрация и обновление установленной PWA **НЕ ПРОВЕРЕНЫ**.
- Реальные экспорты пользователя v13/v14 и личное хранилище не использовались; миграции проверены синтетическими данными.
- Не запускались iOS Safari, Android, скринридер и настоящий пользовательский browser zoom 200%.
- Набор локальных WOFF2-шрифтов **отсутствует**. Зависимость от системных гарнитур сохраняется; требование о гарантированной локальной поддержке кириллицы, латиницы и греческого **не закрыто**.
- `english-diagnostic-bank-v1.json` содержит 0 активных вопросов: вся новая диагностика **недоступна**, пока внешний преподаватель не проверит банк 84 вопросов и права. Никто не присваивал `teacher-verified` и общий CEFR.
- Действующий календарь не заменялся новыми датами по памяти. Актуальность официальных сроков отдельно не проверялась в этом релизном тесте.
- Старые `planner-inline.js`, FIPI и JSON-данные не удалены: возможная чистка требует отдельной проверенной миграции и теста PWA.
- Защита от одновременных вкладок снижает риск перезаписи, но localStorage не поддерживает атомарные транзакции; абсолютная гарантия невозможна.

## 7. Обновление после отдельного разрешения

1. Из работающей v14.6 выполнить **полный экспорт JSON** через штатную кнопку. Сохранить исходный файл и вторую копию в двух разных безопасных местах. Не передавать приватный экспорт третьим лицам.
2. Убедиться, что JSON читается, имеет поле `format: via-classica-full-backup-v1` и необходимые ключи `viaClassica...`. Не редактировать данные вручную.
3. Оставить доступной неизменённую папку или архив v14.6. Не очищать storage/caches установленной PWA.
4. Развернуть **только файлы сайта-кандидата**, не QA и не черновой диагностический банк, на отдельном тестовом HTTPS-origin (или в изолированном профиле с корректным origin). Применить экспорт туда для проверки только после копирования и проверки.
5. Выполнить тесты вручную: ссылка удаляется и не восстанавливается, среда 75/воскресенье 60, субботние чтения, фактическая длительность, словарь, английская первая ошибка, копия и восстановление, два окна, отключение сети, закрытие/открытие установленной PWA, жизненный цикл SW update, отсутствие потери данных, zoom 200%.
6. Вести журнал проходов и тестировать данные **в тестовом профиле**. Не использовать личный рабочий origin для экспериментов с отказом записи.
7. Только после подтверждения владельцем и устранения всех блокирующих проблем можно отдельно согласовывать замену опубликованной версии. Закрыть старые вкладки v14.6 перед переключением.

## 8. Откат

1. Не очищать localStorage, CacheStorage или данные сайта.
2. При появлении проблемы прекратить дальнейшие записи в обеих версиях; сохранить текущую полную резервную копию, если приложение её позволяет скачать корректно.
3. Вернуть неизменные файлы v14.6 на origin, предварительно проверив их SHA-256 из исходного архива; не копировать отдельные старые JS поверх новой версии вперемешку.
4. Проверить обновление старого Service Worker и загрузку старых файлов при наличии сети (при проблемах можно сменить версию кеша в отдельном безопасном патче, но не очищать данные пользователя).
5. Восстановление старой JSON-копии **не автоматическое**: это может потерять действия, совершённые после её создания. Сначала сравнить данные и получить явное согласие владельца на возврат к конкретному состоянию.
6. Проверить ключевые сценарии v14.6, включая удаление, настройки, словарь и экспорт. Новые поля/отдельный ключ диагностики могут игнорироваться старой версией; не удалять их без согласованной миграции.
