# Via Classica · v14.8-p2 · КАНДИДАТ (НЕ УСТАНАВЛИВАТЬ БЕЗ ПРИЁМКИ)

Дата: 28 октября 2026. Основа — **неизменённый кандидат v14.7-p1**, в котором уже выполнены F1/F3/F4. Выполнены только F2/F11 и связанные документы/офлайн-ресурсы. `planner.js`, `english.js` и `storage-guard.js` по содержимому не изменены.

## Что сделано

1. `via-classica-schedule-current.json`: шесть фиксированных занятий в полном соответствии с `DEFAULT_RECURRING` внутри `planner.js`: понедельник 75, среда 60, четверг 90, суббота «Чтения» 90, суббота Speaking Club 90, воскресенье 60; резерв 30 минут после каждого. JSON **справочная синхронизированная копия**, а `planner.js` — фактический источник инициализации. JSON не загружается в планировщик и не может перезаписать изменения пользователя.
2. `weeklyTargetMinutes: null`; из HTML удалена неактуальная фраза о норме «7–8 часов»; сохраняются дневной бюджет и отдых.
3. `via-classica-events-current.json`: отдельный строго структурированный редакционно проверяемый источник календаря. Только даты с `verification: verified`, официальным источником и статусом публикации показываются как подтверждённые. Проект расписания «Высшей пробы» присутствует лишь как непроверенная запись (не выводится в календарь). Сведения проверены на официальных страницах 28.10.2026.
4. `calendar.js`: заполняет панель «Этот месяц», показывает дату проверки, этап, ссылку и статус доступности. Использует неопасный `textContent`/DOM, не изменяет пользовательское расписание. Если в месяце нет подтверждённых предстоящих событий — честное пустое состояние. Сетевой сбой без сохранённого источника не выдаётся за отсутствие официальных дат.
5. Для офлайн-доступа добавлены `calendar.js` и JSON-календарь в Service Worker precache; кеш обновлён до `via-classica-v14.8-p2`. После успешной загрузки дополнительно сохраняется источник под новым независимым ключом `viaClassicaEventsV1` (включается в стандартную полную резервную копию).
6. Если дата, статус или адрес официального источника меняется в новой версии JSON, предыдущее значение и новое сохраняются в `history` вместе с датой обнаружения. При исчезновении события из источника оно архивируется и не отображается как действующее. **Ограничение:** автоматическая локальная история действует на том же устройстве; для нового устройства редактор должен при каждом обновлении перенести историю изменений в распространяемый JSON.

## Порядок правки будущих дат

- Найти первичный официальный документ или сайт организатора; ссылки из соцсетей — только наводки.
- Не объявлять проект расписания окончательно утверждённым.
- Обновить проверку источника, `checkedAt` и `sourceVersion`; при изменении уже опубликованной даты внести запись в `events[].history`, чтобы история была видна на чистой установке.
- Проверить статус и часовой пояс. Сведения по 2026/27 не переносить автоматически на последующие годы.
- Запустить регрессию календаря, включая изменение даты и офлайн.

## Ключи пользователя и восстановление

Ключи `viaClassicaV2`, `viaClassicaPlannerV3`, `viaClassicaEnglishV1`, совместимость со старым `viaClassicaPlannerV2` не менялись. Новый `viaClassicaEventsV1` содержит лишь публичные календарные сведения; при возврате к v14.7 или v14.6 старый код его не использует и **его удалять не нужно**.

Перед **любой** установкой скачать полную резервную копию на текущем живом сайте и проверить файл. Проводить проверку кандидата на отдельном origin/профиле. Не очищать localStorage или данные PWA. Держать все старые вкладки закрытыми во время будущего обновления. Переключение на этот релиз требует отдельного разрешения пользователя.

## Откат

1. Сохранить резервную копию текущих данных.
2. Вернуть опубликованные файлы из исходного v14.7-p1 или неизменного v14.6; учесть версию кеша и поведение Service Worker.
3. При необходимости восстановить сохранённую полную JSON-копию через UI **в корректном профиле/на исходном origin**.
4. Не удалять `viaClassicaEventsV1` и другие `viaClassica*` вручную.
5. Базовый снимок календарного источника: в отдельном QA-пакете `calendar_sources/via-classica-events-current-2026-10-28.json`.

## Что протестировано, а что нет

- 35 статических проверок, 31 новый сценарий Chromium/CDP и 61 повторённая регрессия P0/P1; тесты выполнены на изолированном HTML-документе с моделируемыми localStorage и fetch.
