# Via Classica — заключительный repetitio v15.2-r2

**Дата:** 28.10.2026. **Вердикт: RELEASE CANDIDATE — DO NOT DEPLOY.**

Тестировалась **отдельная копия v15.2-r1**; опубликованный сайт и личный браузер пользователя не открывались и не изменялись. Рабочая версия, названная владельцем: **v14.6**; её эталон сохранён. Данные v14.6 в живом браузере не тестировались и сохранность реальных данных при миграции не доказана.

## 1. Точные изменения

Создан кандидат **v15.2-r2**. Из исходных 42 файлов v15.2-r1 изменены ровно **5** (контрольные суммы и отчёт добавлены отдельно):

1. `english.js`: у `#dictFilter` добавлен доступный `aria-label` («Сортировка и фильтрация словаря»); для двух вариантов кнопок удаления слов — контекстные `aria-label` с названием слова. Содержимое словаря, грамматики и алгоритмы проверок не менялись.
2. `index.html`: версии URL `english.js`, `app.js`, `manifest.webmanifest` изменены на `15.2-r2` для получения обновлённых ресурсов; остальной HTML не менялся.
3. `app.js`: параметр версии URL регистрации SW изменён на `15.2-r2`; логика приложения не менялась.
4. `sw.js`: имя кеша и URL затронутых ресурсов изменены на `15.2-r2`; ранее исправленная логика `503` для отсутствующего офлайн JS/CSS/JSON сохранена.
5. `manifest.webmanifest`: изменено только поле `version` на `15.2-r2-candidate`.

**Без изменений:** `planner.js`, `storage-guard.js`, `calendar.js`, `design.js`, `diagnostics.js`, `styles.css`, JSON-источники, иконки, исторические документы, миграционные материалы и остальные файлы исходного ZIP. В корень нового кандидата добавлены `REPETITIO_R2_RELEASE_STATUS_RU.md` и `SHA256SUMS-15.2-r2.txt`, всего 44 файла. Старые документы/контрольные суммы сохранены для истории; актуальны контрольные суммы r2.

## 4. Отдельные ограничения и оставшиеся блокеры

1. **Блокер выпуска:** Chromium отказал прямой загрузке тестового `http://127.0.0.1:8765/index.html` с `net::ERR_BLOCKED_BY_ADMINISTRATOR`, хотя локальный HTTP-сервер отдавал HTTP 200. Поэтому **реальная регистрация SW, install/update/offline installed PWA, cache eviction на настоящем origin НЕ ПРОВЕРЕНЫ**. Моделируемые CacheStorage/Response через Node VM этого не заменяют.
2. **Блокер выпуска:** не использовалось реальное пользовательское хранилище v14.6 и не выполнялась реальная миграция/восстановление/две вкладки с native localStorage. При синтетических legacy данных функции работают, но **нет доказательства, что реальные данные никогда не потеряются**. `localStorage` не поддерживает атомарные транзакции.
3. **Доступность:** проверены клавиатура, размеры и AX-имена; не проверены NVDA/VoiceOver/TalkBack, реальный browser zoom 200%, iOS/Android и экранное чтение контекста. Старый разведочный `body.style.zoom=2` дал переполнение на 8 экранах из 8 при ширине 1280, но **это не настоящий browser zoom**, медиа-запросы не меняют CSS viewport. Эффективная ширина 640 CSS px в reflow-тесте пройдена. Отдельный автоматический тест 18×18 самих чекбоксов был ложноположительной проблемой: кликабельная строка-`label` имеет >=44 px; это повторно подтверждено в независимом E2E.
4. **Границы контента:** у `english-diagnostic-bank-v1.json` **0 активных вопросов**. 84 черновых D1-задания нельзя выпускать до независимой преподавательской экспертизы ключей, прав, сложности и методики; общий CEFR/IELTS Band автоматически не выставлять. Большая часть `english-source-bank-v1.json` — каталог метаданных внешних источников, а не готовые проверяемые упражнения. Полноценный Speaking/длинный Writing и часть F10 остаются незавершёнными.
5. **Графика и сроки:** оба PNG PWA имеют заявленные размеры, отсутствующие локальные зависимости не выявлены. Локальных WOFF/WOFF2 нет: кросс-платформенная поддержка греческих глифов системными шрифтами не подтверждена. Не проводилась проверка актуальности официальных олимпиадных сроков на сайтах организаторов. Неиспользуемые ресурсы не удалялись.

**Решение по приёмке:** все перечисленные автоматические проверки новой сборки пройдены, но из-за непроверенных обязательных real-origin/PWA/Storage/a11y сценариев **безопасный релиз НЕ ПОДТВЕРЖДЁН**. `v15.2-r2` — отдельный кандидат; разрешение на публикацию не получено и не предполагалось.

## 5. Безопасная инструкция обновления (ТОЛЬКО после закрытия блокеров и отдельного согласия владельца)

1. Оставить неизменный `Via_Classica_v14.6_UNCHANGED_BASELINE.zip`. Выполнить на действующем сайте полный экспорт через штатную кнопку в формат `via-classica-full-backup-v1` и сохранить минимум две независимые локальные копии JSON, убедившись в читаемости и ключах (`viaClassica...`). Не пересылать приватный JSON на публичный origin, в репозиторий или QA-архив.
2. Распаковать `Via_Classica_v15.2_R2_CANDIDATE_NOT_DEPLOY_2026-10-28.zip` отдельно; проверить `sha256sum -c SHA256SUMS-15.2-r2.txt`. `index.html` и все JS/CSS/JSON/PWA-ресурсы располагаются в корне. Не смешивать r2 с v14.6 и не публиковать документы QA и синтетический диагностический банк как runtime.
3. На изолированном тестовом HTTPS-origin и в отдельном браузерном профиле установить и проверить PWA, обновление кеша с r1/v14.6, offline, вход/выход, изменения расписания, словаря, ссылок, задач, полный экспорт/восстановление копии, storage-failure, настоящий двухвкладочный конфликт и **реальный browser zoom 200%** + скринридер.
4. Зафиксировать PASS/FAIL с подтверждениями и контрольными суммами. После закрытия всех блокеров получить отдельное **явное разрешение владельца**. Только тогда планировать обновление действующего origin; не чистить site data или кеш пользователя по умолчанию.

## 6. Инструкция отката

1. Остановить редактирование в старых и новых вкладках. Если возможно, экспортировать **текущее** состояние и сохранить его рядом со старым backup: нельзя терять изменения после создания первой копии.
2. Вернуть **целиком** неизменную v14.6 из контрольного архива; **не** подменять отдельные JS старой версии поверх r2. Проверить новый запрос ресурсов/обновление старого SW с сетью.
3. **Не очищать localStorage или CacheStorage** без отдельного согласия и понимания последствий. Старый JSON не импортировать автоматически: он может перезаписать свежие данные. При несовместимости сначала проанализировать ключи и выполнить тестовое восстановление в изолированном профиле.
4. Проверить удалённые фиксированные занятия (`removedRecurringDefaults`), расписание среда 75 / воскресенье 60 в пользовательской копии, субботние чтения, историю английского, словарь, архив ссылок, backup, PWA offline; записать итог.
